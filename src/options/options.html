FactCheck

Keys are stored locally on this device and are only ever sent to the provider you select below. This extension has no server of its own.

This is a cross-checking aid, not a source of fact. A flagged sentence is not a false one, search results are not verification, and AI summaries can be confidently wrong. Read the sources and judge for yourself. Provided as is, with no warranty and no liability accepted.

What this does, and what it does not

As you read a page or watch a video with captions, a small model running on this machine reads each sentence and estimates how check-worthy it is: whether it states a fact that could be looked up and would matter if it were wrong. Those sentences are highlighted on the page and listed in the side panel.

It never decides whether anything is true. A highlight means "this is a factual claim, worth a look", not "this is false". Everything past that point is you pressing a button to go and see what other sources say.

No page text leaves this machine unless you press one of the buttons below. Scanning, scoring and highlighting all happen locally, for free.

Getting started, with no keys at all

  1. Open a news article, then click the extension icon to open the side panel. The badge on the icon counts the claims found on the page.
  2. Press Check sources on a claim. Out of the box this searches Wikipedia, which needs no account and no key.
  3. Press Search in browser to open the same claim in whichever search engine your browser already uses, in a new tab.
  4. Use the arrows at the top of the panel, or Alt+Shift+N and Alt+Shift+P, to step through the claims on the page the way Ctrl+F steps through matches.

That is the whole extension, working, with nothing configured. API keys widen what Check sources can reach; they are not needed to use it.

Where the numbers in the panel come from

Each claim shows a check-worthiness score from the local model, and after a check an evidence reading built from things that can be inspected rather than from an AI's opinion of itself:

  • how much of the claim's distinctive wording appears in each source;
  • whether the source hedges, editorialises or shouts;
  • what kind of outlet it is, which you can override in Settings;
  • whether a source gives a different figure from the claim;
  • whether it was published early enough to be about the right period;
  • if an AI ran, whether each source supports or contradicts the claim;
  • a published fact-check, when one exists, which outranks all of the above.

The panel lists these reasons in plain language under each reading, so you can disagree with it.

API keys: what each one buys you

Every key is optional. Keys are stored in this browser's local storage on this device, are sent only to the provider they belong to, and are never sent anywhere by this extension otherwise. There is no server in this project.

Web search, instead of Wikipedia

Wikipedia is excellent for people, places, organisations and long-standing figures, and useless for anything that happened this week. A web search key puts full results in the panel, with snippets, sources and dates.

  • Brave Search API — api-dashboard.search.brave.com. Create an account, subscribe to the free plan, then copy the key from the API Keys page. Independent index, and the free tier is generous enough for ordinary reading.
  • SerpAPI — serpapi.com/manage-api-key. Returns Google results. The free tier is small, so it suits occasional checking rather than a day of browsing.

Free allowances change; check the provider's current pricing page rather than trusting a number written here. Nothing is ever called automatically, so a quota is only spent when you press a button.

Published fact-checks

  • Google Fact Check Tools — enable the API in a Google Cloud project, then create an API key under Credentials. It is free. This searches verdicts already published by organisations such as Snopes, PolitiFact and Full Fact. Most claims have never been fact-checked, so expect it to find nothing more often than not, and to be worth a lot when it does.

AI summaries

An AI model reads the sources fetched for a claim and reports what they say, including which ones disagree. Four ways to have one, in order of least fuss:

  • Your browser's built-in model — no key, nothing installed, nothing sent anywhere. Shown in the provider list only if this browser actually exposes it. Chrome downloads the model on first use, so the first summary is slow. Brave's Leo has no extension API, so use a local model there.
  • A local model — Ollama or LM Studio, or anything else speaking the OpenAI chat format. Point the endpoint at it, name the model, and no key or account is involved. Your reading never leaves the machine.
  • Anthropic — console.anthropic.com/settings/keys. Keys begin with sk-ant-. The default model here is the cheapest current one; you can name a stronger model in the Model field.
  • OpenAI — platform.openai.com/api-keys. Keys begin with sk-. Any chat model your account can use works.

Hosted providers are paid per request, which is why the AI step is behind its own button and never runs on its own. A summary sends the claim and the search snippets, not the page you are reading.

If something looks wrong

  • Nothing is flagged. Check the panel banner: the site may be on a never-scan list, the page may not be in English, or auto-check may be off.
  • A setting had no effect. Press Rescan. Settings apply to sentences not already judged.
  • Sign-up boxes get flagged. Tell me, or raise the threshold. Page furniture is filtered by rules that no set of rules covers completely.
  • A video is not being read. Turn on subtitles, or press "Open the transcript" in the panel.

Reading the sources

A search snippet is about 150 characters and often cuts off the number the claim turns on. With this on, the top two results are fetched and the paragraphs that mention the claim are used instead. The requests are sent without cookies, so they are anonymous, and they only happen when you press Check sources.

Remembered answers

The same claim checked twice, or two articles about the same event, then costs one call instead of two. Answers are kept on this machine only, in the browser's own storage, and include the text of the claims you checked.

Training data: the ClaimBuster dataset

The model that decides what is worth checking is trained on the ClaimBuster dataset, created by the IDIR Lab at the University of Texas at Arlington. It is a corpus of sentences from United States presidential debates, each labelled by human annotators as a check-worthy factual claim, an unimportant factual sentence, or not a factual sentence at all.

  • Project: idir.uta.edu/claimbuster
  • Dataset: zenodo.org/records/3836810, DOI 10.5281/zenodo.3609356
  • Licence: Creative Commons Attribution 4.0 International, which permits redistribution and derivative works, including commercial use, on condition that the source is credited

A model trained on that data is a derivative work of it, so the credit travels inside model.json as well as sitting here and in ATTRIBUTION.md. The raw data is not redistributed with this project; it is downloaded from the Zenodo record above.

What the labels mean, and do not

ClaimBuster labels whether a sentence is worth checking, never whether it is true. The classifier inherits exactly that scope. Its scores are not truth ratings and are not presented as any.
